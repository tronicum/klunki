# Klunki: overall review, October 2026

Reviewed on 2026-10-31 at main `0275083`, which includes KLD-067 (turn colour) and KLD-064 (hidden-info secrecy).
This was a review only; no code was changed.

KLD-065 (resign) is reviewed from its branch `worktree-agent-a9c0b239e4da92cea` (`a5af409`). I found no
branch or commit for KLD-058b (GoStrategy screens) or KLD-068 (Schiffe placement), so those are covered only
as risks to watch.

Paths are relative to the repo root. `app/` means `klunki/lib/`, `net/` means `packages/klunki_net/lib/src/`
and `engine/` means `packages/klunki_engine/lib/`.

Severity: 🔴 high · 🟠 medium · 🟢 low.

## Executive summary

- **The core is solid and well tested.**
  - The engine, net and app layers are cleanly separated, and the engine is pure Dart.
  - One deterministic move log drives hot-seat play, network play, replay and verification.
  - The suites were run, all green with no analyzer issues: the engine (180 tests, 5 s), net (111 tests,
    10 s) and app (475 passed / 38 screenshot tests skipped, 77 s).
  - The PWA builds as both JS (16 s) and wasm (20 s).
- **Two security holes undercut the network story.**
  - 🔴 Anyone who knows the guest's display name (or its default mark "O") can take over the guest seat
    without the token: `net/host.dart:220`.
  - 🔴 Hidden setups come from 31-bit seeds of a non-secure `Random()`: the deal in the card game and
    "Zufällig" in battleships. A modified guest can brute-force the seed and learn the host's hand or fleet.
    That breaks the KLD-064 promise that a modified guest learns nothing beyond its own view.
- **KLD-065 (resign) and KLD-064 (secrecy) will clash on merge.**
  - KLD-065 is based on `e31aa6a`, before KLD-064.
  - Redacted views don't carry `resignedBy`. The guest checks `player == currentPlayer` on redacted moves, and
    `_onReveal` requires `isOver`.
  - Result: over the network, a resign in battleships or the card games will drop the connection instead of
    ending the game. Merge notes are in "Pending branches".
- **The game shell still lets players lose or cheat in a game too easily.** These items from UX-REVIEW are
  still open:
  - no confirmation on back: over the network, one swipe ends the game for both players;
  - undo stays live in hidden-information hot-seat games (shoot, undo, shoot again);
  - no start cover.
- **Nothing handles the app going to the background.**
  - There is no `AppLifecycleListener`, auto-reconnect or wake lock.
  - A browser host that switches apps to share the room code loses the room after about 10 s of suspension.
- **It is not ready for a store release.**
  - Icons and launch screens are the Flutter defaults, and Android release builds are signed with the debug key.
  - There is no licences/About screen, and the iOS permission texts are German only.
  - The repo licence is AGPL-3.0, which is an owner decision for App Store distribution.
- **Accessibility is good in places, but three games can't be played with a screen reader or keyboard.**
  - Good: live status, tokens, reduced motion.
  - The Four in a Row cells have no semantics, there is no keyboard focus on the web, and battleship target
    cells are about 18–26 dp on phones.
- **Adding chess is straightforward, but bigger games are not.**
  - Adding a game touches about 15 places.
  - `enum Player { a, b }`, the X/O marks, the protocol's single guest and the single-guest relay rooms all
    assume two players. The property and hotel games need an N-player refactor first.
- **There is no CI.** One workflow running the commands above, plus stricter lints, would protect all of this.

## Pending branches: risks and merge notes

### KLD-065: resign (`a5af409`, branch `worktree-agent-a9c0b239e4da92cea`)

**Design.** `Game.applyMove` handles `{'action':'resign','player':…}` once for every game; games implement
`applyPlayMove`/`playResult`; `playerOf(move)` attributes a move.

This is a good choice: resign is a logged move, so it replicates, replays and undoes like any other. It is
also the right pattern for chess draw offers.

**Conflicts.** The branch predates KLD-064 and KLD-067. Expect conflicts in:
- `klunki/lib/transport/network_transport.dart` (the `_shadow` hunk is gone on main);
- `net/guest.dart` and `net/host.dart` (`_replayLog` no longer exists; replay moved into
  `_replaySnapshot`/`_listen`);
- `app/ui/shell/game_screen.dart` (rewritten by KLD-067);
- all 7 ARB files and the generated `app_localizations*.dart`;
- **the binary Noto Sans SC subset TTFs.** Don't pick either side: regenerate them with
  `python3 -I klunki/tool/update_web_fonts.py subset` after the ARB merge.

**🔴 Resign in hidden-information network games will break.** Each of these must be fixed in the merge:
1. `engine/schiffe_view.dart:48-56` (and the card-game and GoStrategy views): `fromJson` rebuilds `_winner`
   but not `resignedBy`. `_resignedBy` is private to the `Game` base class, so a view can't even set it.
   - Effect: after the host resigns, the guest's view is not `isOver`.
   - Then `net/guest.dart:434` throws `reveal before the game is over` and the connection drops.
   - Fix: add `resigned` to the view JSON, give views a way to set it (a protected setter or a constructor
     parameter), and include it in `viewHash`.
2. `net/guest.dart:409` checks `player != _game.currentPlayer` on redacted moves. A resign by the player who is
   not to move then gets "diverged". Use `playerOf(move)`; a view must answer `playerOf` without engine state,
   which it can.
3. `net/guest.dart:331` and `:387` (`_replaySnapshot`, `_onAccepted`) and `net/host.dart:131` (`_listen` for
   resumed logs) still use `currentPlayer`. They need `playerOf`; the branch only patched the pre-064 code paths.
4. The `Redaction.step`/`redactMove` overrides must pass a resign move through unredacted and without a
   commitment. Today `secret` is "the move differs from its redaction" (`net/host.dart:321`), so it is fine as
   long as no redactor rewrites unknown actions. Add a test anyway.
5. `verifyRedactedGame` (`net/secrecy/secrecy.dart`) replays the full log. Check that a resign at index *n*
   followed by `reveal` verifies.
6. `packages/klunki_net/PROTOCOL.md`: the branch says "the protocol version stays 1", but main is at v2.

**Other notes on KLD-065:**
- The resign text in `engine/game.dart` hard-codes `'X'`/`'O'`: one more two-player assumption.
- A fourth app-bar icon on 360 dp phones (undo, names, restart, resign, history) crowds the title. Use an
  overflow menu (UX-REVIEW 2.8).
- Hot-seat undo can take back a resign. That is fine, but say so in the confirmation dialog.

**Tests to add after the merge:** host and guest resign in battleships, the card game and GoStrategy over
`NetworkTransport`, then `GameVerified` on the guest; a resign on reconnect (`welcome` snapshot).

### KLD-058b: GoStrategy screens (no branch found)

- `engine/gostrategy.dart:403` offers `autosetup` seeds 0–9 as "legal moves", and `:416` accepts any int seed.
  - If the screen's "Mischen" uses those seeds, the guest only has to try 10 setups. Even with
    `Random().nextInt(1<<31)` it can be brute-forced once fights reveal pieces (see S2).
  - The screen should send an explicit `setup` move (the redacted move is committed anyway), or a 128-bit
    secure seed.
- Register the game in all the places listed in A4: `gameVisuals`, `GameAccent` in light and dark (the
  `theme.dart:322` TODO), `game_titles.dart` and the illustration.
- Re-run `glyph_coverage_test` after adding strings, and regenerate the zh subset.

### KLD-068: Schiffe placement (no branch found)

- Keep `autoplace` seeds unguessable (S2), or send explicit placements.
- Make the placement cells semantic buttons (X5): today placement is a raw `Listener`
  (`app/ui/games/schiffe/schiffe_board.dart:189-216`).
- Conflict hotspot: `schiffe_board.dart` and its tests.

### KLD-067: turn colour (merged)

- Clean, and the contrast helper `visibleOn`/`inkOn` is good.

## Findings by area

### A. Architecture and code health

**A1 🟢 Layering is good; keep it.**
- The engine has zero Flutter imports, and `klunki_net` is pure Dart. The transports share
  `GameTransport` (`app/transport/game_transport.dart`), and `GameController` treats local and remote moves
  the same way.
- The secrecy design (redacted views, salted commitments, end-of-game replay) is thoughtful and well documented
  in PROTOCOL.md.

**A2 🟠 The pairing UI is duplicated across four screens, and two of the files are oversized.**
- Evidence:
  - `app/ui/pairing/pairing_screen.dart` (741 lines) and `web_join_screen.dart` (387) both have `_openGame`
    (`:150` / `:209`) and `_connect` / `_cancelConnect` / attempt counters (`:563-616` / `:174-238`).
  - `relay_host_screen.dart` repeats the host panel's `_start` / `_teardown` / `_cancel` / `_copyLink`
    (`:103-168` vs `pairing_screen.dart:249-353`).
  - `app/ui/shell/game_screen.dart` is 711 lines and holds the shell, status pill, tokens, result dialog and
    history sheet.
- Impact: every fix to join and host behaviour (S1, S3, U1) has to be made 2–3 times, and the screens already
  differ (the order of the join groups).
- Fix:
  - a `JoinController` and `HostController` (ChangeNotifiers that own the attempt, cancel, error mapping and
    open-game) with thin screens;
  - split `game_screen.dart` into `status_pill.dart`, `player_token.dart`, `result_dialog.dart` and
    `history_sheet.dart`.

**A3 🟠 Errors are classified by matching English text.**
- Evidence:
  - `app/ui/pairing/relay_errors.dart:34-53` and `network_game_session.dart:102,118` match substrings like
    `"no room with code"`, `"is full"` and `"peer left"` in `NetException.message`.
  - `NetworkTransport.mapReason` (`app/transport/network_transport.dart:225-233`) does the same with
    rejection reasons.
- Impact: changing a wording in `klunki_net` silently breaks the UI texts and the reconnect decisions. Raw
  English also reaches users (I3).
- Fix: an `enum NetErrorCode` on `NetException`, `NetError` and `MoveRejected`, with the message kept for logs.

**A4 🟠 Adding a game touches about 15 places, with no single registration point.** The steps today, as they
would go for chess:
1. Engine: `engine/chess.dart` implementing `Game` (with KLD-065: `applyPlayMove` and `playResult`), plus
   `GameEndReason` entries in `engine/game.dart`.
2. `engine/registry.dart`: add a `GameSpec` (with `redaction`/`appReady` where needed).
3. Text adapter `engine/debug/chess_text.dart`, plus 2 switch entries in `engine/debug/debug_console.dart:28,40`.
4. CLI special cases, if any (`net/cli/cli.dart:545` already special-cases GoStrategy).
5. App screen `app/ui/games/chess_screen.dart`, plus `gameScreens` in `app/ui/shell/screen_registry.dart:20`.
6. `app/ui/game_titles.dart` (title switch).
7. `app/ui/game_visuals.dart:43` (tokens and colours) and an illustration in `app/ui/game_illustrations.dart`.
8. `app/app/theme.dart:324` and `:393`: `GameAccent` for light and dark.
9. `app/ui/engine_l10n.dart:11`: the end-reason switch (exhaustive, so the compiler helps).
10. ARB keys in 7 languages, generate, and regenerate the zh font subset.
11. Tests: engine contract test, screen test, `coverage_test`/`translations_test`/`rtl_test` game lists,
    screenshots harness, `integration_test/app_test.dart`.

The pain points:
- the game id is a bare string repeated in about 9 files;
- the titles live in the engine registry (German, `'4 Gewinnt'`) *and* in ARB;
- forgetting steps 6–8 compiles fine and silently falls back;
- the font subset must be regenerated by hand.

Fix (card KLD-078): one `GameModule` per game in the app (id, screen builder, title, visuals, accents,
describer), checked by a test that every `appGameSpecs` id has a complete module. Move the engine titles out
of `GameSpec`.

**A5 🟢 Dead and leftover code.**
- Three unused ARB keys in all 7 languages, confirmed by a script, with no others: `webJoinIntro`
  (`app_de.arb:1180`), `relayAddressAdvanced` (`:1470`) and `webJoinDirectTitle` (`:1530`).
- `cupertino_icons` is an unused dependency.
- `klunki/pubspec.yaml` still has the description "A new Flutter project.", and `klunki/README.md` is the
  Flutter template.
- `FakeDiscovery` lives in `app/net/fake_discovery.dart`; it is test-only (tree-shaken, harmless) and belongs
  in `test/`.
- Debug paths are properly gated: the Debug-Konsole uses `!kReleaseMode` (`app/ui/menu_screen.dart:120`), and
  the e2e hooks are compile-time `--dart-define` (`app/app/test_mode.dart`).
- Test hooks `debugRewriteOutgoing` and `debugReplaceMove` are public on `KlunkiHost` (`net/host.dart:62,347`).
  They are fine for tests, but annotate them `@visibleForTesting`.

**A6 🟢 Naming is mostly consistent.**
- Code is English and UI is German. Game ids are kebab/lowercase, keys are stable (`shell-*`, `pair-*`), and
  the KLD/I18N references in comments are useful.
- Mixed bits:
  - `Card` vs Flutter's `Card`: KLD-027 is still open, and `hide Card` appears everywhere.
  - "Quartett"/"Schiffe" in code next to English names.
  - The marks X/O are defined in four places: `app/ui/shell/player_labels.dart:30`,
    `net/names.dart:49`, `app/transport/network_transport.dart:271` and
    `engine/debug/quartett_text.dart:7`.

### C. Correctness risks (with reproduction ideas)

**C1 🔴 Resign × secrecy merge.** See "Pending branches".
- Reproduction after the merge: host battleships, guest joins, host taps resign. The guest shows "connection
  lost" instead of "X hat aufgegeben".

**C2 🟠 Background and resume is not handled anywhere.**
- Evidence:
  - no `AppLifecycleListener` or `WidgetsBindingObserver` in `app/`;
  - `Connection` times out after 10 s without a message (`net/connection.dart:67-73`; the defaults are in
    `net/guest.dart:81-82` and `app/transport/network_transport.dart:96-97`);
  - the guest only reconnects when the user taps "Neu verbinden" (`network_game_session.dart:169-174`);
  - a relay room closes when the host's socket ends (`net/relay/relay_server.dart:253`).
- Impact:
  - iOS suspends the app (or Safari the tab) when the user switches apps. The session drops, and the guest has
    to notice and tap.
  - For a PWA relay host, the room is gone for good. That happens exactly in the flow "copy the room code,
    switch to a messenger to send it".
  - iOS may also reclaim the native host's listening sockets in the background (KLD-040 is still open).
- Reproduction:
  - Host a room in iPhone Safari, tap copy, switch to Messages for 30 s, come back: the room is lost.
  - Natively: lock the guest phone mid-game for 20 s, unlock: there is a banner but no automatic recovery.
- Fix (card KLD-074):
  - on `resumed`, the guest auto-reconnects with back-off;
  - on `paused`, send an optional `pause` hint so the host shows "Ben ist kurz weg" instead of "verbunden
    verloren";
  - a relay grace period (keep the room for N minutes after the host's socket ends; the host rejoins with a
    room secret);
  - after resume, the native host checks that its listener is alive and rebinds if not;
  - consider a wake lock during the opponent's turn (a new dependency, needs the user's OK).

**C3 🟠 Divergence and protocol errors show up as a plain disconnect.**
- Evidence:
  - `NetworkTransport._onNetEvent` drops `NetError` on the guest (`app/transport/network_transport.dart:356`);
  - a divergence (`net/guest.dart:469`) closes the connection, and the bar then offers "Neu verbinden", which
    can loop.
- Reproduction: a host with `debugRewriteOutgoing` that alters a move: the guest sees only "Verbindung
  verloren".
- Fix: surface `NetError` as a terminal state with its own text and no reconnect button.

**C4 🟠 `Connection` only catches `ProtocolException` and `TypeError` from handlers.**
- Evidence: `net/connection.dart:100-106`. `FormatException`, `ArgumentError` or `StateError` from a malformed
  peer message escape into the zone as uncaught errors, and the connection stays half-open.
- Reproduction: send `{"type":"welcome","v":2,…}` with a `config.game` that makes a factory throw
  `ArgumentError` (any future `fromJson` that throws something other than `TypeError`).
- Fix: `on Object catch (e)`, then `fail('bad message: …')`.

**C5 🟠 `Random(seed)` determinism is assumed across platforms and SDK versions.**
- Evidence: the deals and placements use `dart:math` `Random(seed)` (`engine/quartett.dart:190`,
  `engine/schiffe.dart:250`, `engine/gostrategy.dart:331`). The guest's verification replays on its own
  platform (`net/guest.dart:445`). The Dart docs don't promise that the seeded sequence stays stable across
  SDK releases or compilers (VM, dart2js, wasm).
- Impact:
  - a PWA guest built with another SDK than the native host could fail verification ("Spielverlauf konnte nicht
    bestätigt werden") for the card games;
  - saved games (KLD-079) could stop replaying after an SDK update.
- Reproduction: run the card-game secrecy test once under `dart test -p chrome` and once on the VM with the
  same seed, and compare the deal.
- Fix: a tiny engine-owned PRNG (splitmix64 or xoshiro, or a SHA-256 counter-mode stream that is already in
  `klunki_net`) for every game rule. This also fixes S2.

**C6 🟢 `GameController` reaches into transport internals.** `canUndo`/`undo` type-check `HotSeatTransport`
(`app/game/game_controller.dart:51,78`), and the shell does the same (`game_screen.dart:318`). Move these into
`GameTransport` capabilities (`supportsUndo`, `supportsRestart`).

**C7 🟢 The host rebuilds the whole engine on every malformed move.**
- Evidence: `net/host.dart:295-300` catches *anything* from `applyMove` and replays the full log. A guest can
  spam malformed moves to make the host replay O(n) each time. That is a minor CPU DoS, irrelevant for small
  games and noticeable for long chess or property games.
- Fix: validate the move shape per game before `applyMove` (strict casts, see T4), and rate-limit rejected
  moves per connection.

**C8 🟢 Test flake: the web join loopback test** (`klunki/test/ui/pairing/web_join_screen_test.dart:194`).
- Why it flakes:
  - The sockets run in `Zone.root` with *real* timers (`pingInterval` 100 ms, `netTimeout` 2 s,
    `test/ui/pairing/pairing_test_utils.dart:20-21`), while the test body advances *fake* time.
  - Real I/O only progresses during the short `runAsync` slices of `pumpUntil` (10 ms).
  - Synchronous stretches can run longer than 2 s of wall time under load from the parallel suite: two full
    apps at 1800×1400, `pumpAndSettle`, `pump(6 s)` of frames. The `Connection` stopwatch (real time) then
    times out and the test sees a disconnect.
  - The same pattern explains the earlier e2e flake noted in `docs/tasks/I18N-07-08-offline-fonts.md:67`.
- Fix: a much larger `netTimeout` in tests (for example 60 s; nothing tests the timeout here), or inject a
  clock into `Connection`. Keep `pump(6 s)` only where needed.

### S. Security and privacy

**S1 🔴 Guest-seat takeover by name.**
- Evidence: `net/host.dart:220`:
  ```dart
  if (reconnect && token != _token && name != _guestName) { return conn.fail('session full'); }
  ```
  A newcomer with the *same name* (and no token) is let in, and the real guest's connection is closed
  ("replaced by a new connection", `:226`). Names are shown on screen, sent in clear text and default to the
  mark "O" when empty (`net/names.dart`).
- Impact:
  - On the LAN, anyone on the Wi-Fi who sees the host (mDNS) can take the seat. Through a relay, anyone with the
    room code can.
  - In a hidden-information game the intruder receives the guest's own view: their fleet, their hand.
  - It also combines with S4 (room codes can be guessed).
- Reproduction: `klunki host connect4`; the guest joins as "Ben"; from a third terminal run
  `klunki join <ip> --name Ben`. The real guest is kicked and the intruder plays on.
- Fix (card KLD-069):
  - token-only rejoin;
  - persist the token on the guest (keyed by host and session) so an app restart can still rejoin;
  - for a lost token, the host confirms "Ben möchte wieder beitreten – zulassen?".
  - PROTOCOL.md documents the name rule (l.112-114), so update it too.

**S2 🔴 Hidden setups come from small, non-secure seeds, which breaks the guest-secrecy claim.**
- Evidence:
  - The card-game deal is `Random(seed)` (`engine/quartett.dart:190`). The seed comes from `newGameSeed()` =
    `Random().nextInt(1 << 31)` (`app/ui/shell/game_screen.dart:36`, used by
    `app/ui/pairing/pairing_screen.dart:85,266`; the CLI uses `1 << 30` at `net/cli/cli.dart:87,107`).
  - Battleship "Zufällig" sends `{'action':'autoplace','seed': Random().nextInt(1 << 31)}`
    (`app/ui/games/schiffe/schiffe_board.dart:99`), and the fleet is `Random(seed)`
    (`engine/schiffe.dart:250`).
- Impact:
  - The host's hidden data is a deterministic function of at most 2³¹ seeds.
  - A modified guest can enumerate the seeds offline (a few CPU-minutes to hours, trivially parallel) and keep
    those consistent with what it sees. In the card game that is its own 8- or 16-card hand, which almost
    certainly pins the seed. In battleships it is the hit/miss results, and a handful of shots suffice.
  - The guest then knows the host's whole hand, draw pile or fleet.
  - PROTOCOL.md (l.254) says "A modified guest learns nothing beyond its view". That is not true today.
  - Salts and commitments are fine (`Random.secure`, 16 bytes, `net/secrecy/secrecy.dart:13`).
- Reproduction: in a Dart script, loop `s` over `0..2^31` and build `QuartettGame(QuartettMode.sets, seed: s,
  handSize: 8)`; stop at the first seed whose B hand equals the guest's view, then print A's hand. Abort early
  on the first mismatching card.
- Fix (card KLD-070):
  - 128–256-bit secret seeds from `Random.secure` (`GameConfig.seed` becomes a string or bytes);
  - an engine-owned PRNG (C5);
  - for autoplace/autosetup, send the explicit layout or a 128-bit seed;
  - for fairness, mix in guest entropy (commit/reveal), which the PROTOCOL threat model already lists as open.

**S3 🟠 A link or QR code silently switches the persisted relay.**
- Evidence:
  - `?room=CODE&relay=evil:9000` becomes the shared, persisted relay setting with no prompt
    (`app/ui/pairing/web_join_screen.dart:131-139`, `app/ui/pairing/room_join.dart:151-158` →
    `app/profile/relay_settings.dart:42-45`);
  - the web join screen also auto-connects on open (`web_join_screen.dart:140-144`).
- Impact: one shared link routes all later hosting and joining through an attacker-chosen relay, which sees
  everything in clear text (`ws://`) and can play man-in-the-middle as host or guest.
- Reproduction: open `https://<pwa>/?room=ABCDE&relay=192.168.1.66:9000`, then later tap "Spiel hosten": the
  room is created on .66.
- Fix: use the link's relay for this join only. Persist it only after "Diesen Relay merken?". Show the relay
  host in the join confirmation.

**S4 🟠 The relay can be abused: there are no per-client limits.**
- Evidence: `net/relay/relay_server.dart`:
  - `maxRooms` 500 is global (`:65,130`), and room codes are 5 characters from 31 symbols (≈28.6 M,
    `net/relay/relay_protocol.dart:19-23`);
  - there is no rate limit on `?join=` or `?create`, no per-IP cap, no `Origin` check;
  - the host's pings keep a room alive for ever (`idle.reset` on every host frame, `:282`);
  - the 256 Ki line limit is checked only after dart:io has assembled the whole frame (`:271`).
- Impact:
  - one client can hold all 500 rooms (every host gets "too many rooms");
  - with 500 rooms open, guessing a code takes about 57k tries, which is quick without rate limits. Combined
    with S1, that is a seat takeover;
  - one huge frame can exhaust memory.
- Reproduction: a script opening 500 `?create` sockets that only answer pings. A loop of `?join=` with random
  codes.
- Fix (extend KLD-051):
  - per-IP limits on rooms, sockets and joins per minute;
  - 6–7 character codes;
  - an absolute room lifetime;
  - an `Origin` allow-list;
  - a frame cap at the socket level (or `wss` behind a proxy that enforces it).

**S5 🟠 Plain TCP and `ws` on the LAN, with no limits.**
- Evidence:
  - the NDJSON `LineSplitter` has no maximum line length (`net/channel/socket_channel.dart:15-19`);
  - unlimited pending connections are accepted (`net/host.dart:196`);
  - the WebSocket port has no `Origin` check (documented in PROTOCOL l.340-343).
- Impact: a LAN peer can exhaust memory, and any web page in the guest's browser can probe the host. These are
  accepted PoC limits, but they need fixing before "internet".
- Fix: a cap on line length and pending connections, an `Origin` check on the host's ws server, and `wss` for
  anything beyond the LAN.

**S6 🟢 Name sanitising is good. Local data is small.**
- `sanitizePlayerName` (`net/names.dart`) is applied on both sides, and bidi isolation is used in the UI
  (`bidiName`).
- Stored locally (`shared_preferences`): the language, the player name, the hot-seat names and the relay
  address. The guest token is *not* persisted (see S1).
- Android auto-backup is implicit (`android/app/src/main/AndroidManifest.xml:27-30`). Make it an explicit
  choice.
- On Android, `mobile_scanner` 7.4.2 bundles Google ML Kit (barcode scanning 17.3.0), which sends diagnostics
  to Google. Declare it in the Play Data-safety form, or set

### T. Tests and tooling

**T1 🟠 There is no CI.** There is no `.github/`. A minimal GitHub Actions workflow (card KLD-072) on
`macos-latest` (or ubuntu for everything but iOS):
1. `dart test` in `packages/klunki_engine` and `packages/klunki_net` (15 s), and `dart analyze` in both.
2. `flutter analyze` and `flutter test` in `klunki/` (about 80 s locally).
3. `flutter build web --release` plus `python3 build/web/pwa_finalize.py`, then upload the artefact.
4. `python3 -I klunki/tool/update_web_fonts.py subset --check` (fail if the subset is stale), and
   `dart run tool/check_unused_arb.dart`.
5. Optionally, nightly: `klunki/tool/pwa_relay_e2e.sh` (needs Firefox and Node) and the iOS simulator e2e
   `tool/e2e_ios_sims.sh` (macOS runners).

**T2 🟠 Coverage gaps.**
- No test for the S1 takeover, the S3 relay persistence, divergence UX (C3), app lifecycle, or uncaught handler
  exceptions (C4).
- No network test of resign with redacted games (C1).
- No golden tests; the screenshot harness writes PNGs but compares nothing. Two or three goldens per game in
  one theme would catch layout regressions.

**T3 🟢 Speed is fine.**
- Full app suite 77 s. The slowest tests are the trump full game (about 9 s,
  `quartett_trumpf_screen_test.dart`) and the l10n coverage sweeps (3–5 s each × 14).
- The 38 skipped tests are the screenshot harness without `KLUNKI_SHOTS`.

**T4 🟠 Lints are too lenient.** All three packages are clean on the defaults (`flutter_lints`; the packages
have no `analysis_options.yaml`). A trial run with stricter settings on a scratch copy found:
- **engine, 44 issues:**
  - 15 strict-casts errors, e.g. `engine/connect4.dart:59` assigns `move['col']` (dynamic) to `int`. That is a
    runtime `TypeError` waiting for a malformed move;
  - 7 `avoid_dynamic_calls`.
- **net, 63 issues:** 29 `discarded_futures`, 14 `avoid_catches_without_on_clauses`, 4 `unawaited_futures`.
- **app, 86 issues:** 42 `discarded_futures` and 17 `unawaited_futures`, mostly in the pairing screens
  (`pairing_screen.dart:281,286,579,584,596,610`, `room_join.dart:84,103,121,126`).

Suggested settings: `strict-casts`, `strict-inference`, `strict-raw-types`, `unawaited_futures`,
`discarded_futures` (app only), `cancel_subscriptions`, `close_sinks`, `avoid_dynamic_calls`,
`prefer_final_locals`, `only_throw_errors` (`net/channel/socket_channel.dart:19` throws a non-Exception), and
`package:lints/recommended.yaml` for the two packages.

**T5 🟢 The e2e scripts work but are manual.**
- `pwa_i18n_check.sh` needs an already running server on :8080 (that is the user's port; take a free port by
  default).
- `pwa_relay_e2e.sh --build` writes into `klunki/build/web`, which a running relay may be serving. Build into
  a temp dir instead.
- `e2e_ios_sims.sh` refuses busy ports (good).
- KLD-038a (Android) is still blocked on SDK licences.

### P. Performance

**P1 🟠 The PWA payload is large.**
- JS build: `main.dart.js` 3.38 MB (0.97 MB gzip), `canvaskit.wasm` 7.3 MB, fonts about 2 MB. Roboto is
  3 × 312 KB unsubset, Noto Sans Arabic 2 × 280 KB, Noto Sans SC 2 × 224 KB.
- `assets/NOTICES` is 2.6 MB. It is excluded from precache (`pwa_finalize.py`), but it is still served.
- wasm build: `main.dart.wasm` 2.7 MB plus `skwasm` 5.2 MB. That is a smaller engine, but Firefox and Safari
  fall back to JS and CanvasKit.
- Startup on the first visit is dominated by CanvasKit, and later visits are cache-first (good).
- Fix:
  - subset Roboto to Latin plus the used symbols (about 3 × 60 KB);
  - ship the wasm build with JS fallback (the bootstrap does this automatically with `--wasm`);
  - measure first-load on mid-range Android over 4G.
  - Also check `build/web` for leftovers: `pwa_finalize.py` is copied into the output and only deletes itself
    when run.

**P2 🟢 Rebuild hotspots.**
- Each move triggers 2–3 full shell rebuilds. `setHint` from `build` causes a post-frame `setState` on the
  whole shell (`game_screen.dart:105-111,139`).
- The Four in a Row drop rebuilds all 42 cells per frame (`connect4_board.dart:321`).
- The mill painter redraws the wood grain on every flash frame (`muehle_painter.dart:42-57`).
- Battleship drag recomputes `legalMoves` per cell change (`schiffe_board.dart:93,166-171`).
- None of these is visible on current devices. Fix them when touching the files: a `ValueNotifier` for the
  hint, a `RepaintBoundary` with a static painter layer.
- Every `shouldRepaint` is a real comparison (good).
